# Tablas de frecuencias, de resumen y de contingencia (y cómo automatizarlas con funciones propias)

En esta lección se aprende a construir tres tipos de tablas que aparecen una y otra vez en los informes de investigación social y educativa: la tabla simple de frecuencias, la tabla de resumen estadístico y la tabla cruzada o de contingencia. Se aprende también a presentarlas con un formato cuidado mediante el paquete `flextable` y, por último, a empaquetar todo ese trabajo en funciones propias para no tener que reescribir el mismo bloque de código cada vez.

El recorrido tiene tres momentos. En el primero las tablas se construyen paso a paso, a mano, porque ese es el momento en que se entiende qué contiene cada tabla y de dónde sale cada número. En el segundo se muestra cómo ese mismo código, una vez comprendido, se envuelve en funciones. En el tercero se rehacen las mismas tablas, pero ahora invocando las funciones. El aprendizaje central está en el primer momento; los otros dos enseñan a reutilizar lo aprendido.

## Dos momentos dentro de cada tabla

Conviene tener clara una distinción que se repite en todos los casos. Construir una tabla en R ocurre en dos pasos separados.

El primer paso produce un objeto de datos: una tabla "de trabajo" con las filas y columnas correctas, pero sin formato de presentación. El segundo paso toma ese objeto y le da apariencia de tabla publicable (encabezados en negrita, alineaciones, tamaños de letra, anchos de columna) mediante `flextable`. Separar ambos pasos permite revisar primero que los números sean correctos y, recién después, ocuparse de cómo se ven.

## Crear rangos a partir de una variable cuantitativa

Una variable cuantitativa como la autorregulación toma muchos valores distintos, de modo que una tabla de frecuencias sobre ella tendría tantas filas como valores observados y resultaría ilegible. Por eso, antes de tabularla, conviene agruparla en rangos.

Primero se observan los cuantiles de la variable, que indican los valores por debajo de los cuales queda el 25 %, el 50 % y el 75 % de los casos.

```r
quantile(df$autorregulacion)
```

A partir de esa información se crean los rangos con `chop_quantiles()` (del paquete `santoku`). El argumento `probs` define los puntos de corte como cuartiles. El argumento `left = TRUE` indica que cada intervalo incluye su extremo izquierdo, y `raw = TRUE` hace que los cortes se expresen con los valores reales de la variable y no con las posiciones de los cuantiles.

Si a `probs` se le pasan nombres, esos nombres se usan como etiquetas legibles de cada rango. Esa es la versión recomendada, porque los rangos quedan descritos en términos comprensibles para quien lea la tabla.

```r
df <- df %>% 
  mutate(
    rangos_autorregulacion = chop_quantiles(
      autorregulacion,
      probs = c("10 a 27" = .0,
                "28 a 31" = .25,
                "32 a 34" = .50,
                "35 a 40" = .75),
      left = TRUE,
      raw = TRUE
    )
  )
```

Si los nombres se omiten, `santoku` genera etiquetas automáticas con la notación de intervalos. La versión con nombres propios es preferible cuando la tabla se va a presentar a un público no técnico.

# Primer momento: construir las tablas paso a paso

## La tabla simple de frecuencias

Una tabla simple de frecuencias responde a una pregunta básica: cuántos casos hay en cada categoría de una variable. Por eso tiene tres elementos. La frecuencia absoluta (cuántos casos, que aquí aparece como `f`), el porcentaje que representa esa categoría sobre el total (que aparece como `%`) y una fila de total que suma todas las categorías.

La tabla se construye con `tabyl()` (del paquete `janitor`). Antes de tabular se convierte la variable `area` en factor con un orden definido, para que las categorías aparezcan en el orden deseado (urbana primero, rural después) y no en orden alfabético. Luego `adorn_totals("row")` agrega la fila de total, `adorn_pct_formatting(digits = 2)` da formato de porcentaje a la columna correspondiente, y `comma(n)` agrega el separador de miles a la frecuencia. La última instrucción renombra las columnas a etiquetas presentables.

```r
tabla_simple_janitor <- df %>% 
  mutate(area = factor(area, levels = c("Urbana", "Rural"))) %>%
  tabyl(area) %>% 
  adorn_totals("row") %>% 
  adorn_pct_formatting(digits = 2) %>% 
  mutate(f = comma(n)) %>% 
  select(Área = area, 
         f, 
         `%` = percent)
```

El objeto `tabla_simple_janitor` ya contiene los números correctos. El segundo paso le da formato con `flextable`. Se ponen en negrita los encabezados, se centran los encabezados de las columnas numéricas, se alinean a la derecha los valores numéricos del cuerpo (para que los dígitos queden alineados), se reduce el tamaño de letra y se fijan los anchos de cada columna.

```r
flextable(tabla_simple_janitor) %>%
  bold(part = "header") %>%
  align(j = 2:3, align = "center", part = "header") %>%
  align(j = 2:3, align = "right", part = "body") %>%
  fontsize(size = 9, part = "all") %>%
  width(j = 1, width = 0.5) %>%
  width(j = 2:3, width = 0.5)
```

## La tabla de resumen estadístico

Mientras la tabla de frecuencias describe una variable categórica, la tabla de resumen describe una variable cuantitativa mediante sus principales medidas: la media, la mediana, la desviación estándar, el mínimo, el máximo y el rango (la diferencia entre el máximo y el mínimo).

El cálculo se hace con `summarise()`, que produce una sola fila ancha con una columna por estadístico. Esa forma ancha es incómoda de leer, así que con `pivot_longer()` la tabla se reorganiza en formato largo: una columna con el nombre del estadístico y otra con su valor. El resultado es una lista vertical de medidas, más fácil de leer en un informe.

```r
tabla_resumen <- df %>% 
  summarise(
    Media = round(mean(autorregulacion, na.rm = TRUE), 3),
    Mediana = round(median(autorregulacion, na.rm = TRUE), 3),
    `Desviación estándar` = round(sd(autorregulacion, na.rm = TRUE), 3),
    Mínimo = min(autorregulacion, na.rm = TRUE),
    Máximo = max(autorregulacion, na.rm = TRUE),
    Rango = (Máximo - Mínimo)
  ) %>% 
  pivot_longer(cols = everything(), names_to = "Estadístico", values_to = "Valor")
```

El argumento `na.rm = TRUE` indica que los valores faltantes se ignoran en cada cálculo. El formato con `flextable` sigue la misma lógica que antes, ajustado a que esta tabla tiene solo dos columnas.

```r
flextable(tabla_resumen) %>%
  bold(part = "header") %>%
  align(j = 2, align = "center", part = "header") %>%
  align(j = 2, align = "right", part = "body") %>%
  fontsize(size = 9, part = "all") %>%
  width(j = 1, width = 1.5) %>%
  width(j = 2, width = 0.5)
```

## La tabla cruzada o de contingencia

Una tabla de contingencia cruza dos variables categóricas para mostrar cómo se distribuyen los casos según la combinación de ambas. En este caso se cruzan los rangos de autorregulación (en las filas) con el área (en las columnas). Cada celda indica cuántos casos comparten un rango y un área, y permite ver si la distribución de la autorregulación cambia entre lo urbano y lo rural.

La tabla se construye con `crosstable()` (del paquete `crosstable`). El primer argumento es la variable que va en las filas, `by` define la variable que va en las columnas, y `total = "both"` agrega totales tanto por fila como por columna. La función produce algunas columnas auxiliares (`.id` y `label`) que no se necesitan, así que se eliminan, y la columna de categorías (llamada `variable` por defecto) se renombra a una etiqueta legible.

```r
tabla_cruzada <- df %>% 
  rename("Área" = area) %>% 
  crosstable(
    rangos_autorregulacion,
    by = "Área",
    total = "both"
  ) %>% 
  rename(`Rangos autorregulación` = variable) %>% 
  select(-c(.id, label))
```

Por defecto, cada celda muestra la frecuencia absoluta y, entre paréntesis, el porcentaje calculado por fila. Conviene tener presente cómo se leen esas celdas al interpretar la tabla.

El formato con `flextable` aquí es un poco más elaborado, porque las columnas correspondientes a las áreas deben quedar agrupadas bajo un encabezado común. Eso se logra con `add_header_row()`, que añade una fila de encabezado superior, y `merge_v()`, que fusiona verticalmente las celdas idénticas (de modo que la etiqueta de la primera columna y la del total ocupen una sola celda alta). El argumento `colwidths = c(1, 2, 1)` indica que el encabezado "Rangos autorregulación" abarca una columna, "Área" abarca dos (las dos áreas) y "Total" abarca una.

```r
flextable(tabla_cruzada) %>%
  add_header_row(values = c("Rangos autorregulación", "Área", "Total"),
                 colwidths = c(1, 2, 1)) %>%
  merge_v(part = "header") %>%
  align(j = 2:4, align = "center", part = "header") %>%
  align(j = 2:4, align = "right", part = "body") %>%
  bold(part = "header") %>%
  fontsize(size = 9, part = "all") %>%
  autofit()
```

## La tabla simple para variables de respuesta múltiple

Algunas preguntas de encuesta admiten que la persona marque más de una opción. En esos casos la respuesta queda guardada en una sola celda con las opciones separadas por un delimitador (aquí, un punto y coma seguido de espacio). Una tabla de frecuencias normal contaría cada combinación como si fuera una categoría única, lo cual no sirve.

La solución es separar cada respuesta en varias filas con `separate_longer_delim()`, de manera que cada opción ocupe su propia fila, y recién entonces contar. El porcentaje se calcula sobre el número de personas que respondieron (las filas originales del conjunto), no sobre el número de filas separadas.

```r
df_delim <- read_excel(here("Datos", "Datos limpios", "encuesta_limpia.xlsx")) %>% 
  clean_names()

tabla_simple_delim <- df_delim %>% 
  select(otras_dificultades) %>% 
  separate_longer_delim(otras_dificultades, delim = "; ") %>% 
  dplyr::count("Otras dificultades" = otras_dificultades, sort = FALSE, name = "f") %>%
  dplyr::mutate(`%` = scales::percent(f/nrow(df_delim), accuracy = 0.01)) %>%
  dplyr::arrange(desc(f)) 
```

Como cada persona puede mencionar varias opciones, los porcentajes de esta tabla no suman 100 %: cada porcentaje indica qué proporción de las personas mencionó esa dificultad, y una misma persona se cuenta en varias filas. El formato con `flextable` es igual al de la tabla simple.

```r
flextable(tabla_simple_delim) %>%
  bold(part = "header") %>%
  align(j = 2:3, align = "center", part = "header") %>%
  align(j = 2:3, align = "right", part = "body") %>%
  fontsize(size = 9, part = "all") %>%
  width(j = 1, width = 1.5) %>%
  width(j = 2:3, width = 0.5)
```

# Segundo momento: automatizar con funciones propias

Las tablas anteriores comparten un problema práctico: si en un proyecto hay que producir veinte tablas de frecuencias, habría que copiar y pegar el mismo bloque de código veinte veces, cambiando solo el nombre de la variable. Eso ocupa mucho espacio, se presta a errores y dificulta el mantenimiento (un cambio de formato obligaría a corregir las veinte copias).

La alternativa es escribir una función que reciba la variable como argumento y devuelva la tabla ya armada. Todo aquello que se repite y se quiere automatizar puede convertirse en una función.

## Una función de paquete y una función propia

crosstable() o tabyl() son funciones que vienen de un paquete: alguien las escribió, las documentó y las distribuyó. Pero nada impide escribir funciones propias. Una función personal es simplemente un bloque de código al que se le da un nombre y unos argumentos, de modo que pueda invocarse cuantas veces se necesite. La escribe quien la necesita, para su propio trabajo.

Eso no significa que una función propia se construya siempre desde cero. Algunas se apoyan solo en R base, y entonces no dependen de ningún paquete. Otras, como las de esta lección, combinan por dentro funciones que ya existen en distintos paquetes (tabyl() de janitor, crosstable() de crosstable, separate_longer_delim() de tidyr, entre otras). Lo que aporta la función propia en este segundo caso no es reemplazar esas piezas, sino reunirlas en una secuencia fija a la que se le da un nombre. Cuando una función propia toma piezas de un paquete, requiere que ese paquete esté cargado: si las funciones de esta lección se usan sin haber activado antes sus paquetes con pacman::p_load(), fallarán aunque su código sea correcto.

## Anatomía de una función

Una función tiene un nombre, unos argumentos entre paréntesis (los datos que recibe de afuera) y un cuerpo entre llaves (el código que ejecuta). El resultado de la última expresión del cuerpo es lo que la función devuelve. El cuerpo de las funciones que siguen es, casi línea por línea, el mismo código del primer momento, con la diferencia de que el nombre de la variable ya no está fijo, sino que entra como argumento.

## El script de funciones

El siguiente script reúne las funciones del curso. No se ejecuta para producir tablas: se ejecuta una vez para que las funciones queden disponibles en la sesión. Conviene guardarlo en el repositorio como un archivo aparte (por ejemplo `funciones_tablas.R`) y cargarlo al inicio de cada script de trabajo.

```r
# tablas ----
## tablas simples ----
make_freq_table <- function(data, var, label, levels_order = NULL) {
  var <- enquo(var)
  
  data <- data %>%
    mutate(!!var := if_else(is.na(!!var), "Sin información", as.character(!!var)))
  
  if (!is.null(levels_order)) {
    data <- data %>%
      mutate(!!var := factor(!!var, levels = levels_order, ordered = TRUE))
  }
  
  data %>%
    tabyl(!!var, show_na = FALSE) %>%
    {
      if (is.null(levels_order)) dplyr::arrange(., desc(n)) else dplyr::arrange(., !!var)
    } %>%
    adorn_totals("row") %>%
    mutate(
      f   = scales::comma(n),
      `%` = scales::percent(percent, accuracy = 0.01),
      `%` = if_else(`%` == "100.00%", "100%", `%`)
    ) %>%
    select(!!label := !!var, f, `%`)
}

## tabla de resumen ----
tabla_resumen <- function(df, var) {
  format_value <- function(x) {
    if (is.numeric(x)) {
      rounded_x <- round(x, 3)
      if (rounded_x == as.integer(rounded_x)) {
        return(as.character(as.integer(rounded_x)))
      } else {
        return(sub("\\.?0+$", "", as.character(rounded_x)))
      }
    }
    return(as.character(x))
  }
  
  var <- rlang::ensym(var)
  
  df %>% 
    summarise(
      Media = round(mean(!!var, na.rm = TRUE), 3),
      Mediana = round(median(!!var, na.rm = TRUE), 3),
      `Desviación estándar` = round(sd(!!var, na.rm = TRUE), 3),
      Mínimo = min(!!var, na.rm = TRUE),
      Máximo = max(!!var, na.rm = TRUE),
      Rango = (Máximo - Mínimo)
    ) %>% 
    pivot_longer(cols = everything(), names_to = "Estadístico", values_to = "Valor") %>% 
    mutate(Valor = sapply(Valor, format_value))
}

## tablas para delimitadores ----
select_multiple <- function(df, var, label, delim) {
  var <- enquo(var)
  df %>%
    select(!!var) %>%
    separate_longer_delim(!!var, delim = delim) %>%
    mutate(!!var := str_trim(!!var)) %>%
    dplyr::count(!!label := !!var, sort = FALSE, name = "f") %>%
    mutate(`%` = scales::percent(f / nrow(df), accuracy = 0.01)) %>%
    arrange(desc(f))
}

## crosstable ----
tabla_cruzada <- function(df, var_fila, var_columna, etiqueta_fila) {
  var_columna <- rlang::as_name(rlang::ensym(var_columna))
  
  df %>%
    crosstable(
      {{ var_fila }},
      by = !!var_columna,
      total = "both"
    ) %>%
    select(-any_of(c(".id", "label"))) %>%
    rename(!!etiqueta_fila := variable)
}

# flextables ----
## tabla simple ----
crear_flextable <- function(objeto) {
  flextable(objeto) %>%
    bold(part = "header") %>%
    align(j = 2:3, align = "center", part = "header") %>%
    align(j = 2:3, align = "right", part = "body") %>%
    fontsize(size = 9, part = "all") %>%
    width(j = 1, width = 2) %>%
    width(j = 2:3, width = 0.5)
}

## tabla de resumen ----
crear_flextable_resumen <- function(objeto) {
  flextable(objeto) %>%
    bold(part = "header") %>%
    align(j = 2, align = "center", part = "header") %>%
    align(j = 2, align = "right", part = "body") %>%
    fontsize(size = 9, part = "all") %>%
    width(j = 1, width = 2) %>%
    width(j = 2, width = 0.5)
}

## crosstable ----
flextable_cruzada <- function(tabla, etiqueta_columna) {
  n_cols    <- ncol(tabla)
  n_niveles <- n_cols - 2
  etiqueta_fila <- names(tabla)[1]
  
  flextable(tabla) %>%
    add_header_row(
      values    = c(etiqueta_fila, etiqueta_columna, "Total"),
      colwidths = c(1, n_niveles, 1)
    ) %>%
    merge_v(part = "header") %>%
    align(j = 2:n_cols, align = "center", part = "header") %>%
    align(j = 2:n_cols, align = "right", part = "body") %>%
    bold(part = "header") %>%
    fontsize(size = 9, part = "all") %>%
    autofit()
}
```

Cada función reproduce un bloque del primer momento, con algunas capacidades añadidas que conviene incorporar de una vez para no resolverlas a mano en cada tabla. La función `make_freq_table()` etiqueta los valores faltantes como "Sin información" y permite fijar el orden de las categorías mediante el argumento `levels_order`. La función `select_multiple()` recibe el delimitador como argumento, de modo que sirve para cualquier separador (`"; "`, `";"`, `","` u otro). La función `flextable_cruzada()` calcula sola cuántas columnas de niveles tiene la tabla, así que funciona con dos áreas o con las que sean.

Hay tres símbolos en estas funciones que conviene reconocer, aunque no es necesario dominarlos para usarlas. Los símbolos `enquo()`, `{{ }}` y `!!` permiten que la función reciba el nombre de una columna escrito sin comillas, igual que ocurre al usar `select()` o `mutate()`. El símbolo `:=` permite asignar a una columna un nombre que viene guardado en un argumento. Gracias a ellos, las funciones se usan con la misma comodidad que las funciones del tidyverse.

Una advertencia práctica sobre `levels_order`: la lista de niveles debe incluir todas las categorías que se quieran conservar. Cualquier categoría que quede fuera de la lista se convierte en valor faltante al factorizar y desaparece de la tabla.

# Buenas prácticas al crear funciones propias

Conviene crear una función cuando un mismo bloque de código se repite con pocos cambios y se prevé usarlo varias veces. Si un cálculo se hace una sola vez, escribir una función para él agrega complejidad sin beneficio.

Las funciones propias se mantienen en un archivo aparte (un script de funciones) que se carga al inicio de cada sesión de trabajo. Así, una mejora en una función (un cambio de formato, una nueva capacidad) queda disponible de inmediato en todos los scripts que la usan, sin tener que corregir copias dispersas.

Una función que recibe el nombre de la variable y una etiqueta como argumentos es más reutilizable que una atada a un nombre de columna fijo. Esa es la razón por la que las funciones de esta lección reciben la variable de afuera en lugar de tenerla escrita en su interior.

## Exportar las tablas a Excel

Hasta aquí cada tabla se ha trabajado dentro de R, pero es común que sea necesario llevar tablas a Excel para usar o compartir fuera del proyecto de RStudio o R. Eso se hace con `write_xlsx()`, del paquete `writexl`. La forma más simple exporta una tabla a la vez, y cada llamada produce un archivo distinto:

```r
write_xlsx(tabla_simple_delim, here("Datos","Exportar tablas","tabla_simple_delim.xlsx"))
write_xlsx(tabla_simple_janitor, here("Datos","Exportar tablas","tabla_simple_janitor.xlsx"))
```

Cuando las tablas están relacionadas entre sí (por ejemplo, todas las tablas descriptivas de un mismo informe), conviene entregarlas en un solo archivo con una hoja por tabla, en lugar de varios archivos sueltos. `write_xlsx()` permite esto si en lugar de una tabla recibe una lista de tablas: cada elemento de la lista se convierte en una hoja del mismo archivo.

```r
tablas <- list(
  tabla_simple_delim   = tabla_simple_delim,
  tabla_simple_janitor = tabla_simple_janitor
)
write_xlsx(tablas, here("Datos", "Exportar tablas", "tablas_unidas.xlsx"))
```

El nombre de cada hoja lo toma del nombre del elemento dentro de la lista. Como aquí la lista se construyó con los mismos nombres que los objetos en el entorno de R (`tabla_simple_delim`, `tabla_simple_janitor`), esos nombres, poco legibles para quien abre el archivo en Excel, son los que terminan como pestañas del libro.

Para controlar cómo se ve cada pestaña basta con nombrar los elementos de la lista de forma distinta a como se llaman los objetos en R. Esto se puede hacer directamente al construir la lista dentro de la misma llamada a `write_xlsx()`, sin necesidad de guardarla antes en un objeto aparte:

```r
write_xlsx(
  list(
    "Simple delim"   = tabla_simple_delim,
    "Simple janitor" = tabla_simple_janitor
  ),
  here("Datos", "Exportar tablas", "tablas_renombradas.xlsx")
)
```

Conviene tener presente que Excel limita el nombre de una hoja a 31 caracteres y no admite ciertos símbolos (como `/`, `\`, `?`, `*`, `[` o `]`), de modo que los nombres elegidos para la lista deben ser cortos y evitar esos caracteres.
